### Question 1 (K4 — Chapter 3: gTAA)
**Scenario:**  
A test automation team maintains 400 web automated tests using Selenium. The development team announces a migration from a legacy desktop web UI to a modern single-page React application, as well as native mobile apps (iOS and Android). The business logic and core workflows remain identical.

Which of the following architectural refactorings represents the cleanest alignment with the **gTAA reference architecture**?

- **A)** Rewrite all 400 test cases from scratch in separate repositories for React, iOS, and Android.
- **B)** Keep the high-level test cases in the **Test Definition Layer (Layer 2)** unchanged, and implement new Page Object adapters in the **Test Adaptation Layer (Layer 4)** for React, Appium (iOS), and Appium (Android).
- **C)** Merge all locator definitions directly into the Test Execution Layer (Layer 3) to centralize execution logic.
- **D)** Replace all automated UI tests with unit tests because mobile apps cannot be tested via gTAA.

> **Correct Answer: B**  
> **Rationale:** In gTAA, Layer 2 (Test Definition) isolates business-level test steps and test data from the concrete implementation technology. When the UI technology changes but business rules remain identical, Layer 2 remains unchanged while Layer 4 (Test Adaptation) is updated with new drivers/adapters.

### Question 2 (K3 — Chapter 2: Preparing for Test Automation)
**Scenario:**  
A team evaluates four candidate projects for conducting a test automation **Pilot Project**.

Which candidate is the most appropriate choice according to ISTQB principles?

- **A)** A mission-critical core banking engine facing an audited compliance release next week.
- **B)** A legacy mainframe system scheduled for full retirement in 2 months.
- **C)** An innovative blockchain prototype where 90% of business requirements and architecture are still undefined.
- **D)** A mature, non-critical customer onboarding module with stable requirements, representative technologies, and an enthusiastic team.

> **Correct Answer: D**  
> **Rationale:** A pilot project should be conducted on a non-critical, stable, and representative application where failures will not endanger critical releases, yet lessons learned can be generalized across the organization.

### Question 3 (K3 — Chapter 7: Verifying the TAS)
**Scenario:**  
During a nightly automated CI run of 1,000 tests, 50 tests randomly fail. When the TAE reruns those exact 50 failed tests individually the following morning on the same build, 48 of them pass without any code modifications.

What is the primary root cause and recommended solution?

- **A)** The tests are **flaky** due to asynchronous timing issues or shared mutable test data; replace arbitrary waits with explicit dynamic synchronization and isolate test data per test.
- **B)** The SUT has critical regressions; developers must stop feature work immediately.
- **C)** The test runner is defective; switch to a commercial runner immediately.
- **D)** Delete the 50 tests from the regression suite to maintain a 100% pass rate.

> **Correct Answer: A**  
> **Rationale:** Intermittent pass/fail results on unchanged code define **Test Flakiness**. Common causes are timing race conditions and shared test data. The solution is explicit synchronization conditions and unique per-test data isolation.

### Question 4 (K2 — Chapter 5: Metrics & Reporting)
**Scenario:**  
Which of the following metrics is classified as an **Internal Metric** of the Test Automation Solution?

- **A)** Time-to-market reduction for SUT feature releases.
- **B)** Customer-reported production defects escaped.
- **C)** Ratio of False Positives generated by the automated test suite.
- **D)** Cost of manual regression testing avoided per quarter.

> **Correct Answer: C**  
> **Rationale:** False Positives measure the internal reliability and health of the TAS itself (an internal metric). Options A, B, and D measure the business and product impact on the organization/SUT (external metrics).

### Question 5 (K4 — Chapter 4: Implementation Risks)
**Scenario:**  
An organization is adopting a commercial test automation tool. What is the most effective proactive mitigation strategy against the risk of **Vendor Lock-in**?

- **A)** Purchase a 10-year enterprise license in advance to lock in pricing.
- **B)** Ensure tests are defined using generic keywords/business steps in Layer 2, wrapping all proprietary tool API calls inside dedicated adapters in Layer 4.
- **C)** Never use automated testing tools.
- **D)** Allow the vendor to write and store all test scripts exclusively in their proprietary cloud database.

> **Correct Answer: B**  
> **Rationale:** Encapsulating proprietary tool interfaces inside the Test Adaptation Layer protects the test assets. If the vendor is replaced, only the adapter classes need to be rewritten, preserving all business test logic.

### Question 6 (K3 — Chapter 6: Transitioning Manual to Auto)
**Scenario:**  
A team is selecting tests from a 500-case manual regression repository to automate first. Which test case should receive the **highest priority** for automation?

- **A)** A one-off usability test evaluating color contrast on the footer.
- **B)** A high-risk checkout transaction test that is executed 5 times a day across 8 different browser configurations.
- **C)** An exploratory test exploring creative ways to break the password reset screen.
- **D)** A test for a promotional campaign feature running for only 48 hours.

> **Correct Answer: B**  
> **Rationale:** The highest ROI for automation comes from tests that are high-risk, executed frequently, repetitive, and span multiple target configurations.
